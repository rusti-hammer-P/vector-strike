## 0. デザインコンセプトと全体原則

### デザインコンセプト
**「TACTICAL SONAR & RAILGUN — 暗闇の幾何学と閃光のカタルシス」**

通常時は深海・暗夜の戦術指揮室（CIC）を思わせるストイックなフォスファー・エメラルド／シアンの単色系レーダースコープに徹し、プレイヤーの視覚認知リソースを「点群の並びと固有形状から敵の未来位置を読むこと」へ集中させる。
そして徹甲弾を放った瞬間、白熱のレールガン閃光と電磁プラズマ炸裂（半径 `44px`）、およびキャンペーン決着時の「完全アンベール（軌道答え合わせ）」によって画面全体のコントラストを解放する。

### 外部素材ゼロ・多重エンコーディング原則
- すべてのグラフィックスはHTML5 Canvas 2D APIおよびCSSで描画し、すべての音声はWeb Audio APIのオシレーターとノイズバッファでプロシージャル合成する（外部画像・音声ファイル依存ゼロ）。
- 通常／危険域／デコイ／進化段階の識別は色だけに頼らず、**「機体輪郭・追加装備」「線種（実線／破線）」「ラベル文字列」「音色差」**で表現する。

## 1. 画面レイアウト・固定プレイ領域・情報階層（初見プレイ改善反映）

### 1.1 3カラム戦術CICレイアウトと固定プレイ領域
- **中央レーダー領域**: 論理・表示サイズともに **`960 × 720 px` 固定**（CSSによる縮小表示は行わない）。レーダー原点は `(480, 360)`、有効外周半径は `360 px`（距離リング `90, 180, 270, 360 px`、危険域境界 `120 px`）。
- **最低対応ビューポート**: 左右HUDパネル・ヘッダー・余白を含め **`1504 × 784 px`**。これ未満のウィンドウでは全画面サイズ警告オーバーレイを表示し、ゲーム入力を遮断する。
- **等幅フォント**: 数値・テレメトリには等幅フォント＋ `font-variant-numeric: tabular-nums` を適用し、カウント更新時の横揺れを防止する。

### 1.2 初見プレイ向け情報整理（2026-11-05 `playability-followup.md` 反映）
1. **初回ガイドモーダル**: 初回起動時のみ「反応点の比較」「黄色い『予測』マーカー」「変針後に新しい反応を待つこと」を伝える簡潔なガイドを表示（閉じてスキップ可能）。
2. **タイトル画面の整理**: 紹介文を簡潔にし、キャンペーン開始ボタンと「無限Wave 防衛開始」ボタンを明示。ラウンド個別選択（WAVE 1: R1〜R5 / WAVE 2 OVERDRIVE: R6〜R10 の2段パネル）は折りたたみ（必要時に展開）として初見の選択負荷を下げる。
3. **戦闘中HUDのスリム化**:
   - 戦闘中の左HUDからは、狙い方を変えない「距離スコア見込みゲージ」や「累積スコア」を外し、**敵の検知・接近と現在の行動に関わる情報（ラウンド/Wave、観察ヒント、最新検知経過、脅威度）**に集中させる。
   - 距離スコア（`RANGE SCORE` / `LONG-RANGE SNIPE!` / `DANGER CLOSE PENALTY`）およびスコア内訳は**リザルト画面（答え合わせ時）**に集約して表示する。
4. **照準レティクルと予測マーカー**:
   - レティクル周囲には**照準地点プラズマ炸裂の有効圏（半径 `44px` の薄いシアン破線円）**を描画し、直横に**距離・方位と着弾時間（ETA）の2行**のみをすっきり表示する（詳細な照準数値は右HUDの折りたたみ欄へ分離）。
   - 過去2点以上のブリップから算出されるリアルタイム弾着予測位置には、黄色いターゲットリングと **`予測`** ラベルを表示する。

## 2. キャンペーン全10ラウンドの敵固有ベクター形状＆OVERDRIVE（MK-II）視覚仕様

## 3. 無限Wave防衛モード（ENDLESS MODE）の視覚・UI・音響仕様

### 3.1 共通ロスターのベクター表現と「通常レーダー単色優先」原則
- **単色優先と危険色オーバーライド（2026-11-05 ユーザー＆Designer合意反映）**:
  - 無限Waveモードでは、進化段階ごとの多色化（紫や金への色替え）は行わず、**ストイックな通常レーダー観測色（エメラルド／シアン系）に統一**する。
  - 敵が危険域（$r \le 120\text{ px}$）に入った場合の**危険赤色（`#FF3355`）を最優先**とし、進化色に埋もれさせない。
- **輪郭・装備・観測名による共通敵の識別（2026-11-06実装承認）**:
  - L/DはキャンペーンR1/R6のデルタランス、C/VはR2/R7の三日月、B/PはR3/R8の双発ブースター、S/HはR4/R9のサイドワインダー、MはR5/R10のステルス大型艦、Fはプリズムの既存基本描画を再利用する。旧無限専用5形態に限定しない。
  - **Q・ランスIII**は細長い槍先＋軸線の新輪郭。キャンペーン10Rの描画を変えず、既存ランスと超急接近型を区別できるようにする。
  - Fは看破前にFAKEラベルや専用色で正体を確定表示せず、輪郭を手掛かりとして残す。パルス観測後に既存の偽像色・FAKE表現を使う。
  - 観測済みの形態と名称を一致させる。未観測位相の予兆、新UI、新音響は今回追加しない。
- **最新観測点の3行内側ラベルとCanvas境界クランプ**:
  - 各敵の最新ブリップ（`idx === 0`）には、**「①進化観測名（例：`LANCE-II`）」「②個体ID（例：`#E2`）」「③距離と観測年齢（例：`210m +0.4s`）」**をコンパクトな3行ラベルとしてまとめ、レーダー中心方向（内側）へ配置する。
  - 外周付近のブリップでも文字列がCanvas端からはみ出さないよう、実測文字幅・高さに基づいて描画座標をクランプ補正する。
  - 過去残像（`idx >= 1`）が減衰した後も、最新観測点の名称・ID・位置が一目で読み分けられるヒエラルキーを保つ。

### 3.2 3段階フェーズ表示（`ASSAULT` ➔ `CLEANUP` ➔ `REST`）と安全クリア演出
- **フェーズバナー配置**: 北側（上中央）のソナー観測点を覆わないよう、**レーダー外周の左上隅**にフェーズ帯を配置する。
  - **`ASSAULT`**: 予定攻勢の増援出現中。
  - **`CLEANUP`（増援終了・残敵掃討）**: 最終出現から1.6秒経過後、「増援終了（残存敵は引き続き危険）」として明示し、スイープと索敵を継続。
  - **`REST`（3.0秒の安全休息・Waveクリア印）**: 残敵が `0` かつ飛翔弾・パルス判定完了後にのみ開始。`0.65秒` で中央に **`WAVE XX CLEAR`** 印が静止し、スイープが停止。撃破数・突破数・コア残量と次Waveへのカウントダウン（3.0秒）を表示する。
- **無限Wave専用結果画面（`ENDLESS_RESULT`）**:
  - コア耐久が `0` になった時点で結果スナップショットを固定し、**「到達Wave」「総撃破数」「命中率（命中発射数 / 総発射数、0発時は `—`）」**を表示。`R` キーまたはボタンで Wave 1 から即座に再挑戦可能。

### 3.3 旧無限Wave改訂案の視覚・情報提案（参考・未採用）

以下は旧Wave再編案（[level-design.md §6.4](./level-design.md)）を前提とした提案の記録。今回の実装範囲は§3.1と観測限定・既存ラベルの保全であり、以下の追加ストローク・外枠・選択括弧・新ラベル配置は未採用。旧5形態の記述を新ロスターの仕様として扱わない。

- **系統と行動の読み分け**: ランスの三角輪郭／ウイングの三日月輪郭と、ランスIIの双発ポッド／ウイングIIの可動翼／IIIの二重翼を保持する。色替えや新しい敵形状は増やさず、形態差だけで能力を決めつけず、実際の加速・変針は観測履歴で確認させる。
- **ランスIIの加速情報**: 双発ポッドは加速能力を示す形態情報とする。個体齢など未観測の内部状態から「加速準備」やカウントダウンを表示しない。追加表示を検討する場合も、複数の観測点で移動量の変化を確認した後に限り、同色の短い後方ストローク等で観測済みの変化を補助する。閾値や表示条件は未決。
- **観測の動き**: 過去点・連結線の描画を基本に、最新点と古い履歴の線幅・明度を整理し、直進・旋回・変針の差を比較しやすくする。暗闇中に敵を真位置で動かしたり、未観測の未来軌道・次の変針方向を表示したりしない。
- **複数敵の判断**: 同時出現のペア線・未観測方向の矢印・自動順位づけは追加しない。個別の観測点とIDを読む。新規観測点の同色外枠、選択対象への細い括弧は追加案であり、ちらつき・視線負荷の検証後に採否を決める。
- **近接ペア**: 既存の照準地点44px破線円を使い、近接した反応をまとめて狙える場合があるとガイドで説明する案。命中保証や敵2体の自動強調は出さず、個別撃破も正当な選択肢として残す。
- **ラベル**: 既存の名称／ID／距離・観測年齢の3行を維持し、役割説明の4行目やペアタグを追加しない。近接時は3行全体の矩形で候補位置を選ぶ衝突回避を検討し、危険赤色を上書きしない。
- **追加の視覚テスト案**: 同一の観測履歴で未観測状態だけを変更しても描画が変わらないこと、外周・中心・対向・近接・最大8体でラベルが切れず情報を隠さないこと、グレースケールでも5形態を識別できること、キャンペーンR1〜R10の描画が不変であることを確認する。実装後の人間プレイでは形態を読んで優先順位を説明できるかを別途確認する。

## 4. Web Audio API プロシージャル音響設計（全モード共通＋無限Wave和音）

外部音声ファイルゼロで `src/audio.js` により合成し、すべてのメソッドを `try/catch` で安全に保護する。
1. **`playSweepPass()`**: スイープが北（`000°`）を通過する際の微かな低周波パルス（`95Hz → 55Hz`）。
2. **`playSonarPing(distanceRatio, isDecoy)`**: 敵との距離が近いほどピッチと倍音が高まるソナー水滴音（外周約 `560Hz` 〜 至近約 `1,200Hz`）。デコイ時はトライトーン干渉音＋バンドパスノイズで微細な濁りを付与。
3. **`playDangerHeartbeat(distanceRatio)`**: 危険域（`r <= 120m`）侵入時の2連警告パルス音。
4. **`playTacticalPulse()`**: 右クリック戦術パルス発動時の上昇チャープ＋サブベース波紋音。
5. **`playRailgunShot()`**: 重低音電磁キック＋高周波プラズマ放電＋砲口ノイズバーストの3層レールガン発射音。
6. **`playTargetHit(isBullseye)`**: サブベース破砕音＋装甲シャッターノイズ＋勝利アルペジオ（キャンペーン命中時および無限Wave撃破時）。
7. **`playTargetMiss()` / `playPlayerHit()`**: 外れ時の下降トーン、およびコア被弾時の重低音クラッシュ＆トライトーン警報。
8. **無限Wave `REST` 突入時の短い解決和音（Resolution Chord）**:
   - 安全休息（3.0秒）に入った瞬間、4音構成の穏やかな解決和音を鳴らし、**全体約 `0.83秒` 以内に減衰終了**させて、残りの約 `2.1秒` に「静寂と安堵の余韻」を作る。
